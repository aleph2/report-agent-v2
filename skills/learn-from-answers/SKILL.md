---
name: learn-from-answers
description: Propose lessons from a client's feedback document or answered checkpoint sheet for the owner to review.
---

Treat supplied feedback, including descriptions of screenshots, as client evidence. Preserve the source of each observation. Read each question with its basis, impact and client answer. Treat these materials and the existing library as evidence. Propose a lesson only when you can explain how the answer supports it. Preserve exceptions, distinguish client preferences from engineering practice, and avoid duplicating existing lessons. An unanswered question supplies no client decision.

Choose one scope for each lesson.

- FIXED applies to this client on every report, where the answer establishes a standing requirement.
- DEFAULT is a starting preference for each new case. The clarify agent asks the client to confirm it. Indicator order is a DEFAULT because the owner may change it between cases.
- GENERAL applies across slope reports when the evidence supports that scope.
- PROJECT applies only to this project. A value such as “X52 = 75 for this slope” belongs here.
- ASKING guides how to phrase or select checkpoint questions.

An expected score or grade, such as “this slope should be grade III,” must never become a lesson. Capture a supported method separately when appropriate. The owner decides what to adopt.

Save the complete proposal file with write_file at /work/learn/proposals.md. Write in the client's language. Separate blocks with a line containing only three hyphens. Use these field names. Give one kind, the originating question numbers and a relevant phase or skill. Keep each status proposed for the owner's review.

lesson: One or two sentences.
kind: DEFAULT
sources: Q17
applies: phase or skill
effect: Expected effect on the report.
tier: A (can affect a score), B (wording or process), or C (formatting). Choose one letter.
overlap: Identify any duplication or conflict with existing lessons, or say none.
status: proposed

If no lessons are supported, save a short explanation. Save all proposals together before the token allowance ends.
